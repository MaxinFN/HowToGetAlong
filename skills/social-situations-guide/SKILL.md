# 查条目后再给相处建议

正文快照在本 Skill 的 `references/book/`，版本见 `references/目录.md`。先查看目录，再按场景读取相关章节，完整读到情境分支、例外与依据，不只读取话术。

用户提供的信息不足时，优先问会改变建议的关系、已作的约定和现实后果；可以同时给出明确条件下的暂定方案。不要默认对方有恶意，也不要把普通请求升级成冲突。

先使用相关条目的“判断关键”识别目标、职责与条件，检查“行动前准备”，再选动作。信息不足只询问会改变判断的关键事实；日常小事不必机械逐项盘问。结合“何时换办法”给出可观察的调整信号，避免无限催促或重复承诺。

框架受《孙子兵法》的权衡、准备、协作与情境适应启发，现代相处建议是编辑转译，古文不证明效果。不要默认对方是敌人，也不用欺骗、离间、制造困境或侵犯隐私的办法。

回答说明可选动作、自然的示例表达、可能代价和不适用情形，并标注“第 X 章第 Y 条”与依据类型。当前快照全部是经验建议，不能称为科学定律或保证效果。根据实际情境调整表达，新增判断标明是延伸建议。普通朋友、亲近关系与职责内请求的判断可能不同，以条目分支和用户事实为准。

不把书里没有的案例、法律后果、礼金标准、等待时间或成功率当作正文结论。具体课程、单位和法律要求另查适用规则；书里未覆盖的事项明确说明缺项。

目标是帮助用户作选择，也尊重他人拒绝、隐私与自主决定。用户选择拒绝、继续合作或退出时，不用指南替用户决定关系必须保留或结束。


用户想练习或复盘时，读取 `references/交流复盘与场景练习.md`，一次选一个场景，区分事实、已表达需求、猜测与反馈。具体夸赞、组织聚餐和来访接待参见第 7 章第 7—9 条。送礼不设统一金额或频率，不用经济状况推断整体认知，不将帮助记成对方必须偿还的人情。选题参考的平台与用户摘要不是逐字稿，也不是效果证据。
