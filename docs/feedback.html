填写读者反馈 · 查看已有反馈

GitHub 反馈会公开显示，提交需要登录。请去掉姓名、联系方式、单位、账号、精确地点及未经同意的聊天截图；无需提供能识别当事人的细节，也不要为填写反馈特意测试高风险冲突。

三个值得反馈的问题

  1. 找得到吗？ 写下实际关键词、筛选及希望找到的场景；没找到也可以反馈。
  2. 知道下一步吗？ 说明哪一步含糊、缺什么条件、什么时候无法执行。
  3. 说得出口吗？ 标出不像日常说话的一句，说明你倾向怎样表达。

只反馈其中一个问题即可，不必完整试用或证明建议有效。反例、拒绝继续尝试和“读完仍不知道怎么办”同样有价值。

征集与采用案例

作者可以邀请少量愿意参与的大学生和职场新人试读，每人选一个熟悉的场景，记录检索、理解和表达上的困难。人数与结果按实际情况记录，不把小范围反馈解释成方法有效率。

采用案例前分别检查：是否有权分享、是否同意匿名改写、是否含可识别信息，以及事实与推测是否分开。未授权的描述不能自动当作获准公开的案例。

当前正文与接续对话仍为本项目编写情境，本次更新没有声称征集到真实案例。以后获准采用时，分别标明“经授权匿名改写的真实案例”与“编写情境”。

如何处理反馈

区分功能问题、表述不清、遗漏情境及不同条件下的反例；复核后决定精修还是新增。不凭一条反馈判断普遍规律，记录修改位置与未解决部分，并同步网页、Markdown、Skill 和 PDF。

反馈不意味着必然收录或立即修复。制度、健康、法律与财务判断需另查适用资料；普通经验仍标明限制与代价。
